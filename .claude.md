# .claude.md - Instructions for AI Assistants

## Role & Goal
You are an assistant helping Leif Christensen work on the **LivingLandscapes** mod for RimWorld. Your goal is to assist with development, design, and optimization of geological terrain generation and gameplay mechanics.

## Workflow & Context Management
This project relies on context management due to token limits. Please follow these rules strictly:

1.  **Single Source of Truth**: The primary memory is the Git repository history, the open GitHub issues, and `tools/Docs/ARCHITECTURE.md` (local, git-ignored; architecture, decisions, roadmap). Do not rely on chat history alone.
2.  **Checkpointing**: Before pausing or when context is low, summarize progress and next steps in `tools/Docs/ARCHITECTURE.md` (roadmap) and as comments on the issues concerned.
3.  **Context Resets**: If you lose context:
    -   Read `tools/Docs/ARCHITECTURE.md` and `tools/CLAUDE.md` first to understand the current state.
    *   Review recent Git commits (`git log --oneline`) and the open issues for details.
4.  **Communication Style**: Be objective, direct, and focused on the project goals defined in the plan. Avoid vague suggestions; provide specific code or design steps.

## Technical Standards

-   **Code Quality**: Clean, modular, and maintainable code. Use descriptive naming and comments.
-   **Modding Best Practices**: Adhere to RimWorld modding conventions and best practices.

## Testing workflow (map generation)
Two kinds of test runs, both with `tools\run-tests.ps1` (refuses to run while RimWorld is open; exports go to `tools\test-exports\<Tag>-<seed>\`, `summary.txt` holds the invariants):
1. **Static seeds** (default `s1 s4 s5 s7`): the same maps every time. Use them to compare one change against the last, change by change. Tune against them freely, but they alone prove nothing: a fix can overfit four maps.
2. **Random seeds** (`-Random 6`): fresh maps every run, reported by name. Run these **before closing an issue or merging**, with the invariants and a look at the maps. A failure is a regression the static maps hid: replay it with `-Seeds <seed>`, file it as a GitHub issue naming the seed, and fix the cause, not the seed.
- Also cover the forced setups a change touches (`-Extra "-ll-quit-delay=1 -ll-mutators=RiverDelta"`, `-ll-hilliness=...`), since random seeds rarely hit mutators.
- Do not close an issue on a static-seed pass alone. State in the closing comment which random seeds passed.
- **Forced tiles** (most RimWorld tiles have no river or coast, so the world's own tiles cover few cases): `-ll-biome=Desert`, `-ll-rainfall=300` (mm), `-ll-temperature=25`, `-ll-elevation=500`, `-ll-hilliness=...`, `-ll-mutators=A+B`, `-ll-coast` or `-ll-coast=North|East|South|West` (the sea lies that way), `-ll-rivers=Creek,River,~HugeRiver` (one link per land neighbour; `~` = river mouth into the coast). Coast and river mutators follow as world generation assigns them (RiverDelta, Headwater, RiverConfluence, River). Build a matrix of conditions (dry/wet biome x flat/mountainous x river/no river x coast) instead of relying on the four static seeds or on pure randomness. The mod `Modify Tiles at Game Start` (Hali.ModifyLandingTile, in the Steam workshop folder) sets biome and landmarks interactively in dev mode: useful for the owner to inspect a tile by hand, not for automated runs.

## Test batteries (owner, 2026-10-20)
- A full battery (static + random seeds + forced tiles) is slow. While fixing issues, run only the few cases the change touches (`-Seeds`, or a handful of cases) and commit. Run the **full battery once**, after the outstanding bug fixes are committed, before closing issues or merging.
- Run batteries in parallel with `tools/run-parallel.ps1 -Cases "s1|","s5|-ll-coast=South -ll-rivers=River,~River","random|" -Workers 3` (one RimWorld instance per worker, ~8 s of wall time per map with 3 workers). Results come from each run's `summary.txt` and `log.txt` in the export folder, not from the game's shared Player.log.
